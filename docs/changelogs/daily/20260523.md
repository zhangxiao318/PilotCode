### 2. 多智能体编排 7 项改进（P-EVR 核心增强）

| # | 改进项 | 核心变更 |
|---|--------|----------|
| **#1** | Worker Specialization | `_llm_worker` 按类型注入不同约束：`simple` 禁用 Glob/Grep/Search；`complex` 加载全项目上下文、使用 POWERFUL 模型；`debug` 禁用 FileWrite/Sleep |
| **#2** | LLM-driven L3 Review | `CodeReviewVerifier` 升级为 LLM 驱动的语义评审（逻辑正确性、设计一致性、回归风险），失败时回退到启发式规则 |
| **#3** | Multi-Agent Swarm | 对 COMPLEX/VERY_COMPLEX 任务启动 Architect → Implementer → Tester → Reviewer 四级代理流水线 |
| **#4** | Verification Synergy | L1 静态分析 / L2 测试编译结果通过 `execution_result.artifacts` 传递给 L3，评审 Prompt 中嵌入前置验证发现 |
| **#5** | Dynamic Redesign | 实现 `_redesign_mission()`：rework ≥2 次的任务自动降级复杂度、减半 max_lines；第二次 redesign 直接标记 REJECTED |
| **#6** | Inline Verification | `_llm_worker` 工具循环中，FileWrite/FileEdit/ApplyPatch 成功后立即运行轻量 L1+L2 检查，问题注入 system message |
| **#7** | Enhanced Exploration | `explore_codebase` 增强为四阶段：文件扫描 → tree-sitter 符号索引 → 轻量调用图分析 → 架构模式检测（MVC/Layered/Plugin/Services） |

### 3. Reasoning 内容治理

- **发送时过滤**：`MessageNormalizer._normalize_for_openai()` 根据模型 `capabilities.reasoning_content_field` 自动剥离不支持的模型的 `reasoning_content`，防止 token 浪费
- **Capability Benchmark 扩展**：新增 `test_reasoning_support`（检测模型是否返回 reasoning_content）和 `test_token_accuracy`（检测 API usage 字段），结果显示在报告 "Model Properties" 区块
- **报告修复**：`_run_capability_benchmark` 正确传递 benchmark results 到 `format_evaluation_report`，修复 Model Properties / Individual Test Results 空白问题

### 4. Web UI Token 实时刷新

- **Web 端 token 推送**：`web/server.py` 在每次 `tool_result` 发送后追加 `context_usage` WebSocket 消息，工具执行期间 token 计数不再冻结
- **SessionService 统一推送**：`_emit_tool_result` 同时触发 `StatusUpdate(token_count=...)`，CLI/TUI/Web 三端同步受益
