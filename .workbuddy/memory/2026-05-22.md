## 创建 context_window_stress_test.py

**任务**: 为 PilotCode 编程智能体创建独立的上下文窗口压力测试脚本，验证 token 估算准确性。

**脚本位置**: `D:\Source\2026\P2\PilotCode\context_window_stress_test.py`

**用法**:
```bash
python context_window_stress_test.py                          # 默认运行
python context_window_stress_test.py --model deepseek         # 指定模型
python context_window_stress_test.py --rounds 10 --target-fill 0.8
```

**测试结果（本地模型 Qwen3-Coder-30B-A3B-Instruct-FP8-q8_0）**:
- tiktoken (token_utils): **+15.7%** 偏差 → **较差**
  - 原因: tiktoken 不认识 Qwen3 模型名，fallback 到 len//4，且没有消息格式 overhead
- heuristic (TokenEstimator): **-1.5%** → **优秀**
- PreciseTokenizer (/tokenize 端点): **-0.15%** → **优秀**

**关键发现**: `token_utils.count_messages_tokens` 对非 OpenAI 模型（如 Qwen）估算误差>15%，因为它使用 tiktoken 但 Qwen3 模型名不在 tiktoken 的模型注册表中，导致 fallback 到字符数/4 估算，且未加消息格式 overhead。

## 修复 context_window_stress_test.py 的 DEBUG 输出噪音

**问题**: `token_utils.py` 内部的 `count_tokens()` 函数在第15、20行有硬编码的 `print(f"DEBUG count_tokens: ...")` 语句，每次调用都会打印，导致脚本输出非常嘈杂。

**修复**: 在 `_estimate_tiktoken()` 方法里用 `contextlib.redirect_stdout(io.StringIO())` 包裹调用，屏蔽底层模块的 DEBUG print，同时保留脚本自身的输出。同时在 import 区加入了 `contextlib` 和 `io`。

**根因**: `token_utils.py` 第15行和第20行有两处 debug print，属于遗留调试代码，应在修复 token 估算 bug 时一并清理。
